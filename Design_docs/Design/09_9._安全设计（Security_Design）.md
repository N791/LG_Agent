## 9. 安全设计（Security Design）

由于平台涉及企业源码、内部知识库及开发环境配置，因此安全设计作为系统建设的重要组成部分。

> **当前实现与目标声明**
>
> 本章列出的 LDAP、OAuth2、企业 SSO、完整资源级授权、网络隔离、企业 DLP 与完整审计属于目标能力。当前实现以 JWT、角色 guard、Prisma 数据持久化、规则过滤和基础 Docker 资源限制为主。

### 9.0 已收敛的安全 seam

1. **认证配置 locality**：`AuthConfigModule` 提供经验证的 JWT 密钥、算法与期限；Auth、JWT strategy 与 Notification gateway 不读取 fallback secret。
2. **组织作用域**：tenant actor 与 organization-scoped repository/authorization interface 对 Course、Task、Workspace、Submission、Conversation、Discussion 强制组织过滤，客户端 `organizationId` 不能决定访问范围。
3. **Sandbox 策略**：默认 Docker adapter 禁用网络、使用 non-root 与 read-only rootfs、drop capabilities、启用 `no-new-privileges`，并执行镜像 allowlist/digest、PID、CPU、内存和并发配额。
4. **AI 审计**：统一 audit adapter 记录调用主体、组织、conversation、trace、Prompt hash、规则命中、fallback、Token 与成本，不持久化原始 Prompt，并执行 retention policy。
5. **路径 containment**：`ExecutionWorkspaceService` 拒绝绝对路径、盘符、空字节、`..` 与符号链接/junction 逃逸；containment 和清理失败均有 contract test。
6. **启动 seed 门槛**：生产启动不创建默认账号；管理员通过显式一次性 bootstrap 初始化，并在首次登录强制修改密码。

### 9.1 身份认证

支持以下认证方式：

* JWT
* LDAP
* OAuth2

### 9.2 权限控制

采用 RBAC（Role-Based Access Control）模型。

系统角色包括：

| 角色      | 权限        |
| ------- | --------- |
| Admin   | 企业管理      |
| Mentor  | 创建课程、查看统计 |
| Trainee | 学习课程      |
| Auditor | 查看日志、审计数据 |

细粒度权限控制到课程、任务及资源级别。

### 9.3 数据安全

平台提供以下数据保护措施：

* HTTPS 全链路加密
* 数据库敏感字段加密存储
* MinIO 对象存储访问控制
* 日志脱敏
* Prompt 敏感信息过滤
* 企业知识库权限隔离

* * *

### 9.4 Sandbox 安全

所有用户代码均运行于 Docker Sandbox 中。

限制包括：

* CPU 配额
* Memory 配额
* 网络访问控制
* 文件系统隔离
* Root 权限禁止
* 超时自动终止

防止恶意代码影响平台稳定性。

#### 9.5.1 文档与代码检索安全（Sprint 17 目标）

1. **检索前授权**：Query Router 只能规划认证主体可访问的 KnowledgeSource、RepositorySnapshot、Task 和 Workspace；关键词/向量/符号候选查询必须包含 Organization Scope 与 ACL。
2. **检索后复核**：rerank、父级展开、`read_symbol` 和关系图扩展后再次校验 Evidence 权限，防止父节点、caller、callee 或 test 跨越资源边界。
3. **不可变来源**：文档 citation 固定到 DocumentVersion，代码 citation 固定到 commit SHA。分支漂移或文档更新不得让旧回答静默指向新内容。
4. **只读 Agent 工具**：代码 Agent 只允许 `search_symbols`、`read_symbol` 和有界 `expand_symbol`；禁止任意路径读取、目录遍历、shell、Git 凭据读取和未授权网络访问。
5. **源码最小披露**：默认返回 L0 符号元数据；仅在回答需要时提升至 L1/L2。调用链、测试和父级展开均设置 Token、深度和节点数上限。
6. **内容不可信**：文档、注释、README、测试名和源码字符串均视为不可信数据；其中的“忽略系统指令”“调用工具”等文本不能改变系统 Prompt、Query Plan 或 tool policy。
7. **缓存隔离**：缓存 key 必须包含 organization、ACL fingerprint、document version/repository commit 与策略版本。权限回收、source 删除或策略升级立即失效。
8. **会话压缩安全**：摘要前执行脱敏；摘要仅保留必要事实和 Evidence ID，不保留密钥、完整源码或已撤权资源正文。
9. **引用防泄漏**：客户端 citation label 不暴露无权访问的仓库名、内部路径或文档标题；打开引用时重新授权，不能依赖生成时权限。
10. **审计最小化**：Retrieval Trace 记录 route、Evidence ID、版本、分数、工具调用和 Token，不记录完整代码库、完整文档或未脱敏 Prompt。

安全测试至少覆盖：跨组织向量召回、全文索引越权、关系图跨 snapshot、缓存投毒、恶意文档 Prompt Injection、符号 ID 枚举、已撤权 citation 打开、会话摘要残留和超预算展开。

### 9.7 系统可观测性

为了保障平台稳定运行，系统建设统一可观测体系。

包括：

* Prometheus 指标采集
* Grafana 可视化监控
* Loki 日志聚合
* OpenTelemetry 链路追踪
* Alertmanager 告警

重点监控：

* API 响应时间
* Sandbox 执行成功率
* AI 请求耗时
* Docker 资源使用率
* 数据库连接数
* Redis 命中率

通过监控、日志与链路追踪形成完整的运维闭环，为企业私有化部署提供稳定可靠的运行保障。

### 9.8 Android 设备与移动数据安全（Sprint 20 目标）

1. **认证**：企业身份使用系统浏览器上的 Authorization Code + PKCE；禁止把密码交给 Android 客户端或在自制 WebView 中完成 OAuth。access / refresh token 由 Keystore 支撑的加密存储保护。
2. **设备会话**：设备注册、push token、平台版本和最近活动均绑定 actor 与 organization；后台撤销、登出、refresh 失败或组织擦除指令触发凭据与受控缓存清除。
3. **锁屏与通知**：push payload 不含源码、完整日志、Prompt、文档正文或内部路径；锁屏默认显示通用文案，登录并重新授权后拉取详情。
4. **本地数据**：默认禁止缓存完整源码、完整 CI 输出、凭据和高敏文档。允许的知识卡/会话摘要需加密并包含组织、ACL fingerprint、版本、TTL；权限回收后不可离线继续访问。
5. **深链与 handoff**：仅允许白名单 scheme / App Link；所有参数按不可信输入处理。handoff token 必须高熵、短期、单次、可撤销，绑定 actor、organization、target 和预期客户端。
6. **日志与遥测**：移动日志、网络拦截器、崩溃报告和 analytics 统一脱敏；不得采集 token、Prompt 原文、私有源码/文档正文或 handoff token。
7. **设备风险**：Root、调试、证书固定、截图限制和 MDM 由组织策略控制。检测失败时按策略阻断或降级；不将厂商不保证的能力表述为绝对防护。
8. **供应链与发布**：依赖锁定和扫描、签名密钥隔离、release signing、Play Integrity/企业分发策略以及 SBOM 纳入发布门禁。

安全测试至少覆盖：跨组织 deep link、被撤权通知打开、push token 接管、handoff 重放/换用户/过期、离线 ACL 残留、Root/调试策略、日志泄密和远程清除。
