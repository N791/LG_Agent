## 2. 技术栈选型（Technology Stack）

项目遵循"成熟、稳定、可扩展、便于私有化部署"原则进行技术选型。

| 模块 | 当前采用 | 状态与说明 |
| --- | --- | --- |
| CLI 客户端 | Node.js + TypeScript + Commander.js | 已实现但进入兼容维护，主要学员体验已转向 Trainee Web |
| 管理端 / 学员端 | React 18 + Vite + Ant Design + Tailwind CSS | 两个独立 SPA |
| Android Mobile Companion | Kotlin + Jetpack Compose + AndroidX | Sprint 20 目标；单向数据流，Navigation Compose，ViewModel/StateFlow；不嵌入 Web IDE |
| 后端 | NestJS 模块化单体 | 单进程部署；尚无独立 API Gateway 或独立 AI/Sandbox 服务 |
| 契约 | `@lg-agent/contracts` | 前后端共享 DTO、枚举与 JSON Schema |
| ORM / 数据库 | Prisma + PostgreSQL | 当前核心持久化路径 |
| 缓存 | Redis | Compose 已提供，但当前核心业务代码未形成稳定 Redis adapter，不得视为已落地依赖 |
| 文件存储 | MinIO | Compose 已提供，但 Workspace 与知识库当前主要使用数据库/本地文件或内存实现 |
| AI | LangChain OpenAI adapter + 自研 Prompt/RAG pipeline | `IVectorStore` 支持 Memory 与 PostgreSQL pgvector adapter；未使用 LlamaIndex 或 Milvus |
| 异步执行 | PostgreSQL lease queue + durable event log | Database adapter 支持 lease、heartbeat、重试、dead-letter 与重启恢复；in-process adapter 仅用于单实例/测试，尚不需要 RabbitMQ/Redis queue |
| Sandbox | Docker CLI + `node:20-alpine` | API 进程启动容器；当前只支持 Node runtime profile |
| CI/CD | GitHub Actions + Turborepo | 构建、Lint、类型检查、测试与镜像发布 |
| 部署 | Docker Compose / Helm | Compose 当前仅定义 PostgreSQL、Redis、MinIO；Helm 部署 API 与 Web |
| 移动认证与本地安全 | AppAuth / OIDC PKCE + Android Keystore | Sprint 20 目标；加密令牌与受控缓存，禁止自制 OAuth WebView 流程 |
| 移动网络与缓存 | OkHttp + Kotlin Serialization + Room（仅白名单数据） | 契约生成/适配、弱网重试；默认不缓存源码、完整日志与高敏知识 |
| 移动推送 | `NotificationTransport` port + FCM adapter | Sprint 20 目标；国内/私有化替代通道通过 adapter 扩展，领域模块不直接依赖 FCM |

技术选型遵循以下原则：

1. 优先采用成熟开源技术，降低维护成本。
2. 保持模块独立，方便未来拆分微服务。
3. 支持企业私有化部署，不依赖公网服务。
4. AI 模块采用 Provider 模式，可自由切换模型。
5. 所有组件均支持容器化部署。
