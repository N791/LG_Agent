## 8. 核心 API 设计（Core API Design）

> **Source of truth**
>
> 路由、请求体与响应 Schema 以 NestJS controller 生成的 OpenAPI 文档为准；本文只维护领域级 endpoint map、认证约束和异步协议，不手工复制完整 payload，避免双份契约漂移。全局前缀为 `/api/v1`，Swagger UI 为 `/api/docs`。

### 8.1 统一约束

- 当前客户端直接访问 NestJS API；独立 API Gateway 属于目标形态。
- 除显式 `@Public()` 路由外，接口使用 Bearer JWT，并由全局 JWT / Roles guard 执行认证授权。
- 跨包 DTO、枚举和 JSON Schema 放在 `@lg-agent/contracts`。
- HTTP 响应由全局 interceptor 统一封装；SSE 使用 `text/event-stream`，不套普通 JSON envelope。
- 资源查询必须从认证主体推导 user / organization scope，不允许把客户端传入的作用域直接当成授权依据。

### 8.3 Submission lifecycle

`POST /submissions/run` 是唯一目标入口：

1. 从认证主体获取 `userId`；
2. 从持久化 Workspace 创建 `SUBMIT` 版本；
3. 创建 `PENDING` Submission 并返回 `submissionId`；
4. 执行状态迁移为 `RUNNING`；
5. 通过 SSE 发布日志与结果事件；
6. 持久化 `PASSED` / `FAILED` / `ERROR`、score、logs、report；
7. 按策略触发 Achievement、Notification 与 AI Review。

旧的 `POST /api/v1/training/submit` 已移除；提交的唯一入口为 `POST /api/v1/submissions/run`。

### 8.4 SSE 契约

Sandbox 与 Submission 日志事件使用 `ExecutionEventDTO`，事件类型至少包括：

```text
RUNNING | LOG | SUCCESS | FAILED | ERROR | COMPLETE
```

所有 SSE data frame 使用 `VersionedSseEventDTO`，当前 `version` 为 `1.0`；流结束发送 `event: done` 与 `type: DONE` 的版本化事件，不使用普通 JSON response envelope。

- 客户端断线重连不能保证重放历史事件；
- 订阅请求必须由资源 owner / authorized mentor 校验；
- 多 API 实例不能共享执行状态或取消操作；
- API 重启不会续跑 Submission。

需要上述能力时，在不改变客户端 interface 的前提下增加持久事件日志和 durable queue adapter。

### 8.5 AI Chat 契约

当前入口为 `POST /api/v1/ai/tutor/chat`，核心字段来自 `ChatRequestDto`：

- `taskId`
- `action`
- `content`
- `stream`
- `conversationId`（可选）
- `activeFile`（可选）

`stream=true` 时返回 SSE；否则返回 `LLMResponse`。所有调用必须经过 Prompt pipeline、敏感信息过滤、LLM Gateway、Provider adapter 和响应过滤。

### 8.6 AI Knowledge & Code Retrieval 契约（Sprint 17 目标）

`POST /api/v1/ai/tutor/chat` 继续作为学员 AI 导师的唯一高层入口。客户端不负责选择向量库、reranker 或 AST parser；服务端根据 action、问题、活动文件和任务上下文生成 Retrieval Plan。

`@lg-agent/contracts` 需要新增以下稳定契约：

- `RetrievalRouteDTO`：`DOCUMENT | CODE | MIXED | TASK_STATE | CONVERSATION`
- `DisclosureLevelDTO`：`L0 | L1 | L2`
- `EvidenceDTO`：统一文档/代码证据、版本、locator、分数、披露层级和 citation label
- `CitationDTO`：文档的 document/version/section/page，或代码的 repository/commit/path/range/symbol
- `RetrievalTraceSummaryDTO`：route、cache hit、候选/入选数量、Token 使用和降级状态
- `KnowledgeIndexJobDTO`、`RepositoryIndexJobDTO`：版本化索引任务与 readiness

AI Chat 普通响应和 SSE 完成事件均返回 `answer + citations + traceSummary`。流式正文可以先到达，但 `done` 事件必须携带最终 citation 列表；客户端不得从 Markdown 文本猜测来源。

内部 tool/port 契约：

```text
search_documents(query, filters, limit) -> Evidence<L0>[]
expand_document(evidenceId, direction, budget) -> Evidence<L1|L2>[]
search_symbols(query, snapshot, filters, limit) -> Evidence<L0>[]
read_symbol(symbolId, level) -> Evidence<L1|L2>
expand_symbol(symbolId, relations, depth, limit) -> Evidence<L2>[]
assemble_context(plan, evidence, tokenBudget) -> ContextEnvelope
```

- `read_symbol` 和 `expand_symbol` 是服务端 Agent 工具，不暴露任意 path/file read。
- 所有 tool 调用从认证主体和 Task/Workspace 推导 organization、repository、snapshot 与 ACL。
- tool 返回稳定错误码：`EVIDENCE_NOT_FOUND`、`SOURCE_FORBIDDEN`、`INDEX_NOT_READY`、`VERSION_STALE`、`BUDGET_EXHAUSTED`、`PARSER_UNSUPPORTED`。
- `ContextEnvelope` 必须包含实际 Token 预算、选中/丢弃 Evidence、会话摘要版本和安全过滤结果。

计划中的管理接口（未实现，不加入当前 endpoint map）：

| Method / Path | 用途 |
| --- | --- |
| `POST /api/v1/ai/knowledge/sources/:id/index` | 为指定文档版本创建索引任务 |
| `GET /api/v1/ai/knowledge/index-jobs/:id` | 查询文档索引状态与失败原因 |
| `POST /api/v1/ai/code/repositories/:id/snapshots` | 解析固定 commit 并创建代码索引 |
| `GET /api/v1/ai/code/snapshots/:id` | 查询 parser、symbol、relation 与 readiness |
| `POST /api/v1/ai/retrieval/preview` | Mentor/Admin 预览路由、Evidence 与 citation，不调用生成模型 |

### 8.7 契约治理

- CI 生成 OpenAPI 后必须执行 breaking-change 检查。
- Controller 的匿名 body 类型应逐步迁移到 `@lg-agent/contracts` DTO。
- 每个 deep module 维护 interface contract test；Submission 状态机、Workspace reconciliation、Executor adapter、租户隔离和 SSE 授权是优先测试面。
- 文档中不得列出未注册的 provider 或未实现 endpoint。
- 文档/代码 Evidence、citation 和 Agent tool 必须维护 contract test；任何 locator 字段变更都视为潜在 breaking change。
- OpenAPI 只描述外部 HTTP/SSE 契约；内部检索 port 由 TypeScript contract 与架构测试治理，禁止为了复用而暴露任意源码读取 API。

### 8.8 Android Mobile Companion 契约（Sprint 20 目标）

以下为计划契约，未实现前不加入 8.2 当前 endpoint map。Android 优先复用现有 Task、AI、Submission、Notification 和 `/me/permissions`，仅为高频首页与跨设备接续增加稳定聚合接口。

| Method / Path | 用途 |
| --- | --- |
| `GET /api/v1/mobile/home` | 当前计划、今日任务、阶段、阻塞、下一步、最近反馈的授权 read model |
| `GET /api/v1/mobile/tasks` | 支持状态游标分页的学员任务列表 |
| `GET /api/v1/mobile/tasks/:taskId` | 任务目标、前置条件、六阶段进度、知识卡摘要、`requiresPc` 和最新验证状态 |
| `GET /api/v1/mobile/submissions/:submissionId/summary` | 结论—原因—行动三层摘要；不返回完整原始日志 |
| `POST /api/v1/device-registrations` | 注册/轮换 push token 与设备能力；幂等且绑定当前 actor / organization |
| `DELETE /api/v1/device-registrations/:id` | 注销设备通道并撤销后续推送 |
| `POST /api/v1/handoffs` | 为 task/workspace/submission 生成短期单次 PC handoff |
| `POST /api/v1/handoffs/:token/consume` | PC/Web 登录后消费 handoff；拒绝重放、过期和主体不匹配 |

计划 DTO 包括 `MobileHomeDTO`、`MobileTaskSummaryDTO`、`MobileTaskDetailDTO`、`StageProgressDTO`、`ActionableFailureDTO`、`DeviceRegistrationDTO` 和 `HandoffDTO`。所有 DTO 进入 `@lg-agent/contracts` 并维护 Kotlin 映射/生成兼容测试。

契约规则：

- read model 只聚合现有领域数据，不持有独立业务状态；`nextAction` 由服务端状态/策略计算。
- 列表使用游标分页、ETag / `updatedAt` 和稳定错误码；弱网重试不得重复创建设备或 handoff。
- deep link 与 push payload 只传资源引用；打开后重新执行 Permission 和 Organization Scope。
- AI 继续使用 `/ai/tutor/chat`，Android 传 `taskId`、action、conversationId 和受控 submission 引用，不上传本地拼接的私有上下文。
- handoff token 不得出现在普通访问日志、analytics 或 crash report 中。
